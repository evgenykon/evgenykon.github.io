Five days ago I wrote about **My Books** as an FB2 reader with one Kotlin core and two shells —
Android and macOS. Since then the repository took 31 commits and the app turned into three
platforms with a synced, encrypted library. Same core, same `Block` model, same reading position —
only now the position you saved on the phone also shows up on the Mac and on Windows.

Repo: **[github.com/evgenykon/my-books](https://github.com/evgenykon/my-books)** ·
Releases: **[v0.4.6](https://github.com/evgenykon/my-books/releases/latest)**

## Windows: the third shell

`desktopApp/` is Compose Multiplatform on the JVM, with `shared` compiled to a JVM target. The
reader is not a port of the Android UI — it is a desktop reader: the text column is width-capped so
lines do not run across a 27-inch screen, navigation is `←` `→`, `PgUp`/`PgDn`, space, `Home`/`End`
and the mouse wheel, `Ctrl` + `+/-` changes the font size, and contents, notes and settings are side
panels instead of phone bottom sheets.

Import works three ways: drag a file into the window, `Ctrl+O`, or straight from the command line
(`MyBooks.exe book.fb2`) — the installer registers the `.fb2` association, so double-clicking a book
opens it. Library lives in `%LOCALAPPDATA%\MyBooks\library` as plain JSON plus one `.fb2` per book.

Two packaging details worth the effort: the MSI bundles its own JRE (96 MB, no "install Java
first"), and `MyBooks.exe` and the MSI are signed with a self-signed certificate. Windows still says
"unknown publisher" until you install `mybooks.cer` from the release into Trusted Root Certification
Authorities — after that the publisher is shown. Only a paid OV/EV certificate removes SmartScreen
entirely; I am not buying one for a personal reader.

## Encrypted vaults in git branches

The part I actually wanted: one library across three devices without a server. A vault is a **branch
of a private GitHub repository** — one branch, one vault.

- `vault.enc` holds the manifest (books, notes, reading progress, settings) and
  `books/<id>.enc` holds one encrypted blob per book, so adding a book does not rewrite the whole
  library.
- Crypto: `PBKDF2-HMAC-SHA256`, 200 000 iterations, into `AES-256-GCM`. The file stores only the
  KDF envelope, salt, nonce and ciphertext — the password never leaves the device.
- The GitHub token and each vault's password live in the OS secret store: **DPAPI** on Windows,
  **Android Keystore** (`EncryptedSharedPreferences`), **Keychain** on macOS. The password is asked
  once, when the vault is created.
- Any change (book, note, progress, settings) is pushed to the active branch ~1.5 s later; there is
  also an explicit sync button. Opening a vault on a new device pulls the books down, applies notes,
  progress and settings, and does not duplicate what is already there. Startup now syncs both ways.

Vault names are branch names: lowercase latin, digits and `-`, 1–40 characters, with `main`, `test`,
`windows` and friends reserved.

## Self-updates on Android and Windows

Both apps check `/releases/latest` themselves. Android shows a banner, downloads the APK through a
`FileProvider` and hands it to the system installer; there is also a manual "Check for updates" in
settings. Windows shows a strip above the library, downloads the MSI, quits, installs and relaunches
the app.

The Windows half has a trap that cost me a release: Windows Installer compares **product versions**,
not files, so an MSI with the same version just installs the same product again. `version.txt` now
drives `packageVersion = 1.0.N`, where `N` is the patch number — every release is a real upgrade.

The APK is signed with my own key and installed outside Google Play, so Play Protect warns about an
"unsafe app". That is normal for sideloading: "More details" → "Install anyway". Builds come from
GitHub Actions in this repository, nothing is republished anywhere else.

## Reader work

- **Footnotes**: markers in the text are now clickable and show the note itself — the FB2
  `name="notes"` body I already moved to the back of the book finally became usable.
- **Quotes**: adding a note stores only the selected text, not the whole paragraph; text that is
  quoted somewhere in your notes gets a dotted underline, so you can see what you have already
  marked.
- **Fonts**: four Cyrillic families bundled (Alegreya, Merriweather, PT Serif, Spectral), each with
  regular, italic, bold and bold-italic — no dependency on what the system happens to have.
- Fixes along the way: page height had to exclude the toolbar (otherwise the last line of every page
  was cut), the settings button opened the wrong sheet on Android, and space in the note editor used
  to dismiss it instead of typing a space.

## CI

Every platform is built on GitHub Actions: `Android` (tests + APK), `macOS` (Kotlin/Native arm64+x64
→ `Shared.xcframework` → `swift build`), `Windows` (`:shared:desktopTest`, portable zip with embedded
JRE, MSI). The release workflow publishes assets even when one platform fails, and keeps the macOS
compiler log as a public artifact — the same trick as the deploy here: a build you cannot read the
log of is a build you cannot trust.

No local Gradle builds at all. `:desktopApp:snapshot` renders UI screenshots without opening a
window, which is how the Windows layout gets checked in CI.
