I read a lot of FB2 — it is basically the default format of every Russian e-library — and every
reader app I tried either ignored my notes, lost the reading position after an update, or was a
web wrapper around something else. So I wrote my own: **My Books**, an FB2 reader for Android and
macOS with a single shared core.

Repo: **[github.com/evgenykon/my-books](https://github.com/evgenykon/my-books)**

## The idea: one parser, not two

The interesting part is not the UI. It is that both apps read a book through the *same* code.
The book is parsed once into a flat list of blocks (`Block`), and the reading position is simply
`(block index, character offset)`. No DOM, no attributed strings in the core, no per-platform
parsing quirks — a position saved on the phone opens at the same word on the Mac, and the
percentage is computed in one place (`ReadingProgress`).

```
shared/      Kotlin Multiplatform core: FB2 parser, book model, reading progress
androidApp/  Kotlin + Jetpack Compose
macos/       SwiftUI + CoreText (SwiftPM, core as Shared.xcframework)
```

## What the core does

- **`Xml.kt`** — a fault-tolerant XML reader with zero dependencies, because real FB2 files from
  libraries are broken far more often than you would like. Encodings: UTF-8, windows-1251,
  KOI8-R, Latin-1, UTF-16, plus named entities (`&nbsp;`, `&mdash;`, …).
- **`Fb2Parser.kt`** — title info (name, authors, annotation, cover), the body (headings,
  paragraphs, epigraphs, poems, images), a table of contents built from `section/title`, and the
  `name="notes"` body moved to the back of the book as footnotes.
- **`Model.kt`** — `Book`, `Block`, `TocEntry`, `Position`, `ReadingProgress`.
- **Tests** in `shared/src/commonTest`: parsing, TOC, block indices, progress, cp1251 and
  UTF-8-with-BOM decoding.

## Android

Import via SAF (no storage permissions at all), a library with progress, deleting a book together
with its notes. The reader paginates by the *real* layout of the text through `TextMeasurer`, shows
book / author / “page N of M” / percent in the header, and has its own text toolbar for
**Copy** and **Add note** — the quote is taken straight from the selection.

## macOS

Import via `fileImporter`, pagination through `CTFramesetter`, page navigation with arrows, space
or swipe. Selection is native (`textSelection(.enabled)` + ⌘C), plus a paragraph context menu with
“Copy paragraph” and “Add note”. Font family, size, line spacing, margins, theme
(light / sepia / dark) and justification work the same way on both platforms.

## Builds

No local Gradle builds — both platforms are built in GitHub Actions:

- **Android** — `:shared:testDebugUnitTest` + `:androidApp:assembleDebug`, the APK lands in the
  `mybooks-debug-apk` artifact;
- **macOS** — Kotlin/Native frameworks are linked into `Shared.xcframework`, then SwiftPM builds
  the app.

That is the whole point of the architecture: the risky, bug-prone half (parsing, positions,
progress) is one Kotlin module with tests, and both UIs are thin shells over it.
